## Deferred And Non-E2E Flows

- Live Telegram Bot API, live Telegram Mini App auth, and live Telegram client rendering are not used in the root E2E suite. They require external network access, bot credentials, signed Telegram payloads, and client state that would make PR checks brittle; root E2E instead injects deterministic `window.Telegram.WebApp` globals, while backend Telegram route/service tests verify signed payload handling and bot behavior with fakes.
- Live OCR, Voyage embeddings, classification, SEO provider calls, and other paid/provider credentials are not used. The containerized E2E path keeps those providers in fake mode and proves our pipeline/search contracts through deterministic upload, dual-index proof, and backend provider-failure tests.
- Private Telegram uploads, inline result sends, retention commands, and crawler catch-up are intentionally non-browser E2E for now because the user-visible surface is Telegram, not the web app. The backend integration tests listed above exercise those flows with fake adapters, storage, and analytics without calling Telegram.
- Google OAuth and other external account-linking providers are not browser-E2E gated without sandbox credentials. The suite uses deterministic verified email/password full accounts for collection/profile coverage, while backend auth/link route and service tests cover provider-specific contracts.

## Artifacts

Playwright writes reports, test results, screenshots, videos, and traces under `E2E_ARTIFACTS_DIR`, which the one-command runner binds to `.artifacts/e2e/<run-id>/`. The dependency-outage phases use `degraded/<phase>/` below that directory so their reports cannot overwrite the normal suite's results.
